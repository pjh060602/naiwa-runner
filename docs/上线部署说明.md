# 上线部署说明（GitHub Pages 子路径）

目标站点：**https://pjh060602.github.io/naiwa-runner/**

部署形态：仓库 `naiwa-runner` 的 **GitHub Actions** 模式 Pages。构建在 CI 里做，产物是 `game/dist`，
不使用 `gh-pages` 分支、也不需要把 `dist` 提交进仓库（`.gitignore` 已忽略 `game/dist/`）。

涉及的文件（只有这三个）：

| 文件 | 作用 |
| --- | --- |
| `game/vite.config.ts` | 生产构建 `base = '/naiwa-runner/'`，dev / preview 仍是 `'/'` |
| `.github/workflows/deploy-pages.yml` | push 到 `master` → npm ci → npm run build → 发布到 Pages |
| `docs/上线部署说明.md` | 本文件 |

---

## 1. 第一次上线（一次性手工步骤）

### 1.1 建仓库

在 GitHub 网页上 `New repository`：

- **Repository name 必须是 `naiwa-runner`** —— 这个名字就是子路径 `/naiwa-runner/`，改名字就必须同步改
  `game/vite.config.ts` 里的 `PAGES_BASE`，否则整站白屏（见「常见坑 1」）。
- **建空仓库**：不要勾 *Add a README file*、不要加 *.gitignore*、不要选 license。
  加了任何文件都会让第一次 `git push` 撞上 "non-fast-forward / unrelated histories"。
- 可见性随意（Public 最省事；Private 的 Pages 需要 Pro/Team 套餐）。

### 1.2 本地关联远端并推送

在**仓库根目录**（也就是 `奶蛙快跑/`，`.git` 所在处，不是 `game/`）执行：

```bash
cd "D:/Project Files/Agent_project/Deepseek Harness/奶蛙快跑"

# 首次：加远端
git remote add origin https://github.com/pjh060602/naiwa-runner.git
# 已经加过、要改地址时用：
# git remote set-url origin https://github.com/pjh060602/naiwa-runner.git

git push -u origin master
```

推送的是 `master` 分支（工作流 `on.push.branches` 只监听 `master`）。若你本地分支叫 `main`，
要么在 GitHub 仓库 Settings → Branches 把默认分支设成 `master`，要么把工作流里的 `branches: [master]` 改成 `main`。

### 1.3 打开 Pages（关键一步，容易漏）

仓库 → **Settings** → 左侧 **Pages** → *Build and deployment*：

- **Source 选 `GitHub Actions`**（不是 `Deploy from a branch`）。
  这一步不做，`actions/deploy-pages` 会直接失败（`Get Pages site failed. Please verify that the repository has Pages enabled`）。

### 1.4 等 Actions 变绿

仓库 → **Actions** → `Deploy to GitHub Pages`：

- 两个 job：`build` → `deploy`。
- 首次部署 `deploy` 会停在 `Waiting for approval` 是正常的：它绑定了 `github-pages` environment。
  点进这次运行 → **Review deployments** → 勾选 `github-pages` → **Approve and deploy**。
  （也可以在 Settings → Environments → github-pages 里删掉 Required reviewers，以后就全自动。）
- 绿了之后 `deploy` job 的摘要里会打印 `page_url`。

### 1.5 打开网址

**https://pjh060602.github.io/naiwa-runner/**

之后每次 `git push origin master` 都会自动重新构建部署，不需要再碰 Settings。

判断标准：**这几行都必须以 `/naiwa-runner/` 开头**。出现 `src="/assets/...` 或 `href="/models/...`

### 2.3 用 preview 起一个「真·子路径」预览

⚠️ **不能直接用 `npm run preview`**。`vite preview` 内部是以 `command: 'serve'` 解析配置的，
按 `game/vite.config.ts` 的规则会拿到 `base: '/'`，与 `dist/index.html` 里已写死的 `/naiwa-runner/`
前缀不匹配，结果全站 404。必须用命令行参数显式覆盖 `base`：

```bash
cd game
npm run build
npm run preview:pages     # = vite preview --base /naiwa-runner/ --port 4187 --strictPort
```

实际输出：

```
  ➜  Local:   http://localhost:4187/naiwa-runner/
  ➜  Network: http://10.105.192.171:4187/naiwa-runner/
```

（`preview:pages` 这个脚本就是为此加的，端口 4187 避开 dev 的 5173 和 `npm run preview` 的 5174。
直接 `npx vite preview --base /naiwa-runner/` 也行，但别省 `--base`。）

**本地想直接玩**（不用管 base）：`cd game && npm run play` → http://localhost:5173/
用的是 dev server（base 为 `/`），改代码即时生效。

## 3. public 资源在子路径下是否还要额外改动？

**不需要。** 依据：

1. `game/index.html` 里两个绝对路径预加载（`/models/naiwa_front_tex.png`、`/models/naiwa_laugh_tex.png`）
   是 Vite 的 HTML 资源处理范围（`<link href>`），构建时会被改写成 `/naiwa-runner/models/...`
   —— 见 2.2 的产物原文。所以 **`index.html` 不需要改**。
2. 运行时资源全部走 `import.meta.env.BASE_URL`：
   - `src/core/config.ts`：`CLIP_LAUGH_URL = 'audio/laugh_mid.mp3'` 等是**相对**串，由
     `src/audio/audio.ts` 用模板字符串把 `import.meta.env.BASE_URL` 与相对路径拼起来再 `fetch`；
   - `src/character/chaser.ts` / `naiwa-billboard.ts` / `src/world/naiwa-texture.ts`：`BASE + 'models/xxx.png'`。
   构建时 `BASE_URL` 被内联成 `"/naiwa-runner/"`，产物里能直接看到
   `fetch` 调用与模型贴图 URL 都带 `/naiwa-runner/` 前缀（`dist/assets/*.js` 里能直接搜到），且
   `dist/assets/*.js` 中**没有任何** `'/models/'`、`'/audio/'`、`'/refs/'` 这类根绝对字面量。

**新增资源时的纪律**：一律写成 `BASE + 'models/xxx.png'` / `import.meta.env.BASE_URL + '...'`，
不要在 `src/**` 里手写 `'/models/xxx.png'`（这种字符串 Vite 不会改写，上线必然 404，而本地 dev
用 `base: '/'` 又正好是对的 —— 最容易漏测的一类 bug）。`public/refs/*.jpg` 目前只用于美术参考，
不参与运行时加载。

## 4. 常见坑

1. **整站白屏（Console 里一堆 404 `/assets/...`）**
   最常见原因：仓库名 ≠ `naiwa-runner`，或者 `base` 没生效。核对
   `game/vite.config.ts` 的 `PAGES_BASE` 与仓库名一致；再核对 `dist/index.html` 的前缀（见 2.2）。
   如果仓库要换名，改 `PAGES_BASE` → 重新 push → 等 Actions 绿。
2. **只有图片 / 音频 404，页面本身正常**
   说明 `base` 生效了，但某处写了根绝对路径。搜 `src/**` 里的 `'/models/`、`'/audio/`
   （`index.html` 里的 preload 写法是安全的，Vite 会改写）。
3. **Actions 里 `npm ci` 失败**：`game/package-lock.json` 与 `package.json` 不同步。
   本地 `cd game && npm install` 生成新 lock 后一起提交；注意 `cache-dependency-path` 指向的就是这个 lock。
4. **`deploy` job 报 `Get Pages site failed`**：Settings → Pages 的 Source 还没选成 `GitHub Actions`（见 1.3）。
5. **`deploy` job 一直 `Waiting for approval`**：`github-pages` environment 有 Required reviewers，
   去 Actions 里 Approve 一次，或删掉该保护规则（见 1.4）。
6. **push 了但 Actions 没触发**：默认分支不是 `master`，或者推送的是别的分支。
   工作流只监听 `on.push.branches: [master]`；也可以用 **Run workflow**（`workflow_dispatch`）手动触发。
7. **缓存 / 看到旧版本**：`assets/*` 带内容 hash，不会拿到旧文件；但 `index.html` 由 Pages CDN
   缓存（分钟级）。部署绿了还看到旧版，先 `Ctrl+F5` 强刷，再等 1–2 分钟。
   移动端可以加个查询串避开缓存：`https://pjh060602.github.io/naiwa-runner/?v=2`。
8. **把 `dist` 提交进仓库**：别提交，`.gitignore` 里已有 `game/dist/`；CI 自己会构建。
9. **`npm run preview` 本地 404**：见 2.3，preview 默认 base 是 `'/'`，要显式 `--base /naiwa-runner/`。
