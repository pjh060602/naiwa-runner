# 手机真机试玩说明（奶蛙快跑）

> 先说清楚：**我没有真机**。这份说明里的操作步骤是可靠的（都是标准做法），但"在 iPhone/安卓上到底什么感觉"我无法自证——
> 我实际验证过的只有：Chrome DevTools 的 iPhone-14 模拟视口（390×844）渲染，以及 `/touch-selftest.html` 里用真实 `TouchEvent` 跑的 23 项手势断言。
> 下面【未验证】小节把我没验过的都列出来了，请不要当成结论。

## 一、让手机打开游戏

1. 电脑和手机连**同一个 Wi-Fi**（不能是"访客网络"或不同网段）。
2. 电脑上在 `game/` 目录启动开发服务器（`host` 已打开）：

   ```bash
   cd game
   npm install          # 第一次才需要
   npm run dev
   ```

   终端会打印两行地址，第二行 `Network:` 那条就是手机要用的：
   ```
   ➜  Local:   http://localhost:5173/
   ➜  Network: http://192.168.x.x:5173/
   ```

3. 手机浏览器（iOS Safari / 安卓 Chrome）地址栏输入那个 `http://192.168.x.x:5173/`。
4. 想试生产构建就换成：
   ```bash
   npm run build
   npm run preview      # 端口 5174，同样 host 已开
   ```
   手机访问 `http://192.168.x.x:5174/`。

### 打不开的排查（按命中率排序）
- **Windows 防火墙**：第一次跑 `npm run dev` 会弹"是否允许 Node.js 访问网络"，选**允许（专用网络）**。已经拒了就去"Windows 防火墙 → 允许应用通过防火墙"里给 Node.js 打勾。
- 手机和电脑不在同一网段（电脑走网线/公司网络、手机连 Wi-Fi）。
- 路由器开了 **AP 隔离 / 客户端隔离**。
- 公司/学校网络的入站策略直接挡 5173。
- 确认终端里确实出现了 `Network:` 那行；没有就是 `host` 没生效（本仓库已配 `server.host: true`）。

## 二、手机上怎么操作

- **左右滑**：换道（阈值 30 CSS px，横滑取主轴）
- **上滑**：跳
- **下滑**：滑铲；**下滑后手指别松继续按住** = 肚皮滑行（最长 1.4s，松手弹起 0.8m）
- 撞死后**点一下屏幕**重开（或接键盘按 R）
- 建议**横屏**：竖屏能跑，但左右视野窄，换道预判难受

## 三、iOS / 安卓必看：声音

浏览器有自动播放限制，**AudioContext 必须在真实用户手势之后才能启动**。游戏已做处理：第一次触摸/按键时才创建音频。

所以：**进游戏先点一下屏幕**（或滑一下），再开始玩才有声音。
验证：console 里出现这两行就说明音频通道起来了
```
[audio] AudioContext 已创建（sfx / voice 双通道）
[audio] 笑声素材就绪：short, mid, full
```
点了还没声：先检查 iOS **侧边静音拨片**（它会静音 WebAudio），再看媒体音量。

## 四、性能怎么看（自己验）

游戏每 5 秒往 console 打一行：
```
[perf] t=20s fps=118 cpuMs=0.53 drawCalls=74 (max 77) triangles=53400 (max 54204) dist=327m speed=18.5 fov=64.3 tier=mid obstacles=8 bottles=5 | step:60 bottle:8 laugh_short:1
```
手机上看两个数就够：`fps`（目标 ≥40）和 `cpuMs`（逻辑+提交耗时，与刷新率无关，>8ms 该担心）。
像素密度已限制 `devicePixelRatio ≤ 1.5`，高分屏不会因为 3x 像素被拖死。

## 五、我没验证过的事（请真机确认，别当结论）

1. **iOS Safari 的音频解锁时序**：按标准做法实现（首次 pointerdown/keydown/touchstart 创建并 resume），没有在真 iOS 上确认"按一下第一下就出声"。
2. **真机帧率**：我的数字全部来自桌面 Edge/Chrome（fps 110–120、cpuMs 0.5–0.8ms）。中低端安卓的真实 fps 我不知道。
3. **刘海/安全区**：HUD 用了 `env(safe-area-inset-top)`，没在真机确认过刘海屏不遮挡。
4. **多指手势/误触**：手势只跟踪第一个触点（单指），双指或手掌误触未验证。
5. **横竖屏切换**：resize 会重设相机与画布，没在真机做过旋转测试。
6. **手感**：滑铲长按阈值（0.15s 起滑、1.4s 上限）只在键盘上定过，触屏按住曲线没调过。

## 六、出问题时请给我

- 手机型号 + 系统版本 + 浏览器（Safari / 安卓 Chrome / 微信内置）
- console 里 `[perf]` 与 `[audio]` 开头的几行（截图即可）
- 是"打不开"还是"能玩但手感/声音不对"
